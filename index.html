How it works
  • Acurast uses Aura: block production is a round-robin. Every 6-second slot belongs to the collator at position slot mod N in Session.Validators (the “Turn” column).
  • For each block in the window the page reads the slot from the block header and credits the collator whose turn it was. A slot with no block is counted as missed for that collator.
  • “Last block” is CollatorSelection.LastAuthoredBlock, the value the chain itself uses to remove candidates that stopped authoring.
  • If the collator set changed inside the window, only blocks after the change are counted.
  • Times are estimates from slot numbers. Status: On track = authored on its last turn; Missed = its last 1–2 turns passed without a block; Silent = 3 or more.
  • Nothing is stored and there is no backend: your browser asks a public RPC node directly (dishich.com RPC first, Acurast public RPC as fallback) and refreshes every minute.
